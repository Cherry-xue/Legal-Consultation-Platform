## 生成真实法律法规资料集（data/legal-sources）

**背景**：项目知识库此前只有虚构测试材料，`evals/development.json` 里大量用例问真实法条只能走 NO_BASIS。本轮补齐四部核心法。

**产出**：`data/legal-sources/` 下 4 个 txt + `manifest.json`
- 民法典 1260 条 / 108387 字 / domain=general（七编合一，五域皆可检索）
- 劳动合同法 98 条 / 11565 字 / domain=labor
- 消费者权益保护法 63 条 / 7773 字 / domain=consumer
- 民事诉讼法 306 条 / 33585 字 / domain=procedure

**生成脚本**：`scripts/build_legal_sources.py`（可重跑，法律再修正时直接再执行）

**核心原则**：绝不凭模型记忆写法条——那会让项目的引用校验（quote 必须是原文连续子串）变成对着假原文自我验证。只从可核验官方页面提取。

**来源**：民法典/劳动合同法/消法用 beijing.gov.cn 政策文件库（原生全角标点、数字保真、自带发文字号与实施日期）；民诉法用中国法院网吉林高院页，无锡中院页作交叉验证。

**关键踩坑与解法**：
1. 人大公报 PDF 经 pypdf 提取会**丢失阿拉伯数字**（「本法自年月日起施行」），不可用 → 改 HTML 源。
2. 靠「条号连续」正则猜条边界不可靠：法条正文含引用（「依据本法第三百零一条的规定」）会被误判为条文起点，导致第三百条被腰斩。解法：用 HTML 段落结构定位（每条一 `<p>`），文本模式仅作回退。
3. 校验必须能发现错误，不能为通过而放宽：一度只认出 12 条，根因是要求条号前必须是句号，而条文前可能是章节标题。最终改为「后向排除」+ 结构提取。
4. 民法典「第一分编」「第二分编」标题正则要写 `(?:分)?[编章节]`，否则标题会粘到条尾。
5. 转载页会把站点水印（「评价建议」「版权所有」）并进末条，需按词表剥离。

**校验方法（每条都必须过）**：条数精确、条号 1..N 连续、每条以原文条号开头、每条以「。／；」收尾。最终用项目自身 `app.rag.split_text` 复验：四部法切块数与条数完全相等，**article 字段 100% 填对**。

**重要发现（法条版本沿革问题）**：民诉法 2023 修正使条号整体位移，无锡中院转载版的**条文内部交叉引用没跟着更新**（第 215/216/219/222/265 条仍引用旧条号 207、249-251）。核查确认主源正确（第 211 条确为「应当再审的 13 种情形」，第 253-255 条确为执行措施）。这印证了项目待办里「法律版本沿革及过渡适用管理」的必要性——转载文本不能只看条数对就采信。

**入库障碍（待解决）**：`backend/app/main.py` 上传接口限制——非 admin 用户设置 `legal_status != 'unknown'` 或 `visibility == 'public'` 会 403。法条要登记为「现行」且作为公共资料供所有用户检索，必须用 `is_admin=True` 的账号。当前无创建管理员的脚本，且 MySQL/Chroma/API/worker 均未启动。

## 补充：民诉法交叉验证清单结构化

原先 manifest 的 `cross_check` 只存了差异条号列表 `[215,216,219,222,265]`，后人无法复核结论。已改为逐条对照，每条记录 `main_cites`（主源引用哪条）、`other_cites`（副源引用哪条）、`basis`（为何采信主源）。

**差异规律**：副源所有内部引用统一比现行条号小 4 条——215 引 206（现行 210）、216/219/222 引 207（现行 211）、265 引 249-251（现行 253-255）。即副源的**条目标题已按 2023 修正更新**（第 215 条位置正确），但**正文交叉引用仍是修正前编号**。这种"半更新"状态比纯旧版更危险，只看条数完全发现不了。

**验证方法**：用被引用条文的内容反向验证——现行 210 条确为「申请再审」、211 条确为「应当再审的 13 种情形」、253-255 条确为三种执行措施，与各条所需引用一一对应；副源所引 206（司法确认调解协议）、207（申请实现担保物权）、249-251（公证债权文书执行/申请执行期间/执行通知）均与上下文无关。

**踩坑**：抓取「本法第X条」时，并列列举（「本法第二百五十三条、第二百五十四条、第二百五十五条」）后续条号没有「本法」前缀，正则只抓第一个会导致记录误导。需 `本法((?:第X条[、和]?)+)` 再拆，并去重保序。
