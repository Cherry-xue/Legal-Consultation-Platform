# 基于 RAG 与多智能体协作的智慧法律咨询平台：项目需求分析

> 版本：v1.2 · 日期：2026-10-27
> 配套：[项目规划书](智慧法律咨询平台项目规划书.md)
> 修订：以五条正式要求为基线；五个业务 Agent 为必做，协作 Agent 为附加题；统一范围、菜单与验收口径。

## 本轮补充：客户账号、记忆与头像

客户通过注册、登录进入平台，可退出、修改昵称和密码、上传图片并裁剪头像。浏览器不再要求手工填写访问凭据，服务配置和数据库维护仅在后台进行。

- 账号密码哈希存储，登录会话保存在服务端，通过 HttpOnly Cookie 识别身份。
- 会话、消息、记忆、私人资料、运行记录均按认证后的用户 ID 隔离，不能使用客户端传入的身份覆盖。
- 会话可保存、恢复、继续追问和删除。记忆由用户主动添加或删除，区分通用及业务范围，不作为法律证据。
- 头像支持 JPG、PNG、WebP，前端拖动、缩放裁剪，后端校验后统一重编码，不能信任文件扩展名。
- 客户只操作自己的资料；公共知识发布与基础设施维护不出现在客户界面。

| 用例 | 验收 |
|---|---|
| AUTH-01 | 注册、重复账号提示、登录、退出及过期会话处理 |
| AUTH-02 | 修改密码后其他会话失效，非管理员不能访问维护功能 |
| USER-01 | 两个用户互不可读写对方的会话、记忆、私人资料和运行记录 |
| MEMORY-01 | 模型只收到当前用户且适用当前业务范围的记忆及已授权历史 |
| AVATAR-01 | 上传、拖动、缩放裁剪、保存和头像更新；无效图片被拒绝 |

## 一、项目定位与正式要求

本项目面向民商事法律信息检索与辅助场景。用户描述问题后，业务 Agent 调用 RAG 知识库，基于检索证据输出说明、适用条件与引用，用户可以查看原文片段。首期面向青年律师、法务助理及有基本法律信息需求的用户。

五个必做业务 Agent 为合同审查、劳动争议、婚姻家事、消费维权、诉讼程序。基础验收通过后，新增第六个“协作咨询 Agent”，负责跨领域分工与结果汇总。

### 1.1 需求基线与对应关系

| 编号 | 项目正式要求 | 本项目落实方式 | 验收证据 |
|---|---|---|---|
| REQ-01 | 实现至少 5 个业务智能体，每个具备独立业务定位 | 五个业务 Agent，各有职责、提示词、检索范围与输出结构 | 五个业务场景、业务配置及调用记录 |
| REQ-02 | 每个智能体有独立菜单；RAG 全链路有对应菜单 | 五个 Agent 菜单，知识库管理、文本切块、向量检索三个 RAG 菜单 | 基础 8 个菜单可进入并操作 |
| REQ-03 | 文档上传、切块、向量化入库、向量检索、结果展示完整；切块与检索独立入口 | 上传与任务状态在知识库页，预览及确认入库在切块页，查询及原文在检索页 | 新文档经完整链路后可检索 |
| REQ-04 | 每个智能体调用 RAG 完成问答 | 五个 Agent 均调用真实检索服务，答案关联来源 | 每个 Agent 的问答、检索记录与引用 |
| REQ-05 | 菜单切换生效、操作有反馈、可查看原文片段 | 切换实际业务配置与会话，显示任务进度和错误，引用展开原文 | 请求与配置一致、成功失败反馈、原文定位 |

正式要求没有强制五域知识互斥、一域一个向量库、跨域全部拒答、Agentic 多轮检索或多 Agent 协作。独立定位由业务职责与实际行为证明；附加题不替代基础五个 Agent。

### 1.2 用户价值

| 痛点 | 对应能力 | 可验证结果 |
|---|---|---|
| 口语问题难定位资料 | 查询改写、术语辅助及向量检索 | 口语用例召回相关依据 |
| 回答没有出处 | 基于证据生成、引用可展开 | 定位到文档版本与原文片段 |
| 不知道资料是否过时 | 来源、版本、效力与核验时间 | 未知状态不表述为现行有效 |
| 不同业务需要不同输出 | 五个业务 Agent | 风险清单、主张项目、程序材料等输出差异 |
| 同一事项涉及多个领域 | 协作 Agent（附加题） | 可追踪两个业务 Agent 的分工与结果 |

不预设系统必然优于通用模型，增益由相同测试集与明确配置的对照结果说明。

## 二、范围与交付层级

### 2.1 必做：基础验收范围

- 五个独立业务 Agent 及菜单，均支持基于 RAG 的文本问答。
- 文档上传、解析、切块预览、向量化入库、向量检索和原文片段展示。
- 三个 RAG 菜单，各阶段有处理中、成功、失败与重试反馈。
- 原文、文档版本、切块、检索记录和回答引用可追溯。
- 基础来源与版本核验、无依据处理、权限及私人数据隔离。
- 合同 Agent 基础支持粘贴条款问答与风险提示。

### 2.2 附加题：协作咨询 Agent

基础验收通过后实施；独立菜单为“协作咨询”，作为第六个 Agent。

| 项目 | 需求 |
|---|---|
| 定位 | 对同一事项中的跨领域问题分解任务并汇总结果 |
| 输入 | 用户问题、已知事实及可选的发生时间、地区 |
| 分工 | 一次选择两个不同业务 Agent，各自获得明确子问题与必要事实 |
| 执行 | 服务端白名单调用已有 Agent，每个子 Agent 独立调用 RAG |
| 汇总 | 展示分领域结论、共同材料、引用、适用条件、差异与待补事实 |
| 限制 | 一轮协作、最多两个子任务、禁止递归，设置总超时与证据预算 |
| 失败 | 子任务失败时标明部分完成及失败领域，不补造结论 |
| 反馈 | 展示任务分工、子 Agent 状态、来源及最终汇总 |

示例：“网购商品涉嫌虚假宣传，商家拒绝退款，我应该准备什么材料、向哪个法院起诉？”消费维权 Agent 处理责任与救济规则，诉讼程序 Agent 处理管辖及材料。事实不全时列出适用条件和待补信息，不预设一定构成欺诈或已确定管辖。

必须能查看真实子 Agent 调用及各自 RAG 记录；只增加一个通用问答页面不算完成协作。

### 2.3 其他可选增强

- 检索调试页，比较不同参数与检索策略。
- Agentic 多轮检索：争点拆解、充分性判断、改写，最多两轮总检索（首轮加一次重试）。
- 全文合同上传审查、审查立场和合同类型设置、风险清单导出。
- 类案、混合检索、重排序、人工核验的新旧法对应表。
- 多轮记忆、地方性规定及更大资料覆盖。

这些增强分别记录实际完成情况，不作为基础验收前置条件。

## 三、五个业务 Agent

| Agent | 主责问题 | 优先资料 | 主要输出 |
|---|---|---|---|
| 合同审查 | 商事条款理解、常见风险、修改方向 | 民法典相关编、合同解释、官方示范文本 | 条款说明、风险、依据、待确认事项 |
| 劳动争议 | 工资、加班、解除、补偿、劳动仲裁 | 劳动法律、行政法规与司法解释 | 主张项目、条件、时效与材料 |
| 婚姻家事 | 夫妻财产、抚养、继承 | 民法典及婚姻家事、继承解释 | 财产或身份关系说明、规则、待补事实 |
| 消费维权 | 退换货、质量、虚假宣传、平台责任 | 消保、电子商务、产品质量相关规定 | 责任与救济路径、条件、证据 |
| 诉讼程序 | 管辖、起诉、举证、期限、执行 | 民事诉讼法及程序相关规定 | 步骤、材料、期限计算前提 |

独立定位不等于知识互斥。劳动 Agent 可以回答劳动仲裁时效，婚姻家事 Agent 可以提示相关程序。共享法条保持统一版本，通过域标签或关联关系复用，不维护冲突副本。

明显不相关的问题应说明职责并建议切换；相关问题可在主责范围内回答。综合处理可以引导至协作咨询；未启用附加题时提供手动切换建议。不能用“是否拒答”代替菜单切换生效的验证。

## 四、界面与业务流程

### 4.1 菜单清单

| 层级 | 菜单 | 路由 | 职责 |
|---|---|---|---|
| 必做 | 合同审查 | `/agent/contract` | 条款问答与风险提示 |
| 必做 | 劳动争议 | `/agent/labor` | 劳动信息问答 |
| 必做 | 婚姻家事 | `/agent/family` | 家事与继承问答 |
| 必做 | 消费维权 | `/agent/consumer` | 消费纠纷问答 |
| 必做 | 诉讼程序 | `/agent/procedure` | 程序问答 |
| 必做 | 知识库管理 | `/rag/knowledge` | 上传、列表、解析与索引状态 |
| 必做 | 文本切块 | `/rag/chunks` | 参数、预览、确认向量化入库 |
| 必做 | 向量检索 | `/rag/retrieval` | 查询、分数、结果、原文 |
| 附加题 | 协作咨询 | `/agent/collaboration` | 分工、子 Agent 执行与汇总 |
| 可选 | 检索调试 | `/rag/debug` | 策略比较 |

基础 8 个菜单，启用协作后 9 个，全部启用后 10 个。向量化在切块页提供明确按钮与进度，不必另设菜单；未实现的可选功能隐藏入口，不使用空白占位页。

### 4.2 入库闭环

上传并登记来源和版本 → 解析 → 切块预览 → 人工确认 → 向量化任务 → 写索引 → 状态回写 → 查询并查看原文。

保留原文件及定位信息。空文本、损坏文件、扫描件需要 OCR、切块超限或嵌入失败时说明原因及下一步。OCR 可暂不支持，但应明确反馈。只有完成索引的可用版本参与问答。

### 4.3 单 Agent 问答

选择 Agent → 提问 → 权限与配置校验 → 检索 → 检查版本和适用条件 → 草稿 → 引用校验 → 展示回答及来源。

普通回答包含说明、依据、分析、风险或不确定性、下一步。无依据和事实不足时简短说明并列出待补信息，不强制编满五段。引用失败时最多补检索或修复一次，仍失败则删除不受支持结论或返回证据不足。

### 4.4 协作闭环

综合问题 → 分成两个子任务 → 校验白名单及预算 → 调用两个业务 Agent → 收集结构化结果 → 检查前提与差异 → 汇总 → 展示统一引用。

子结果包含任务 ID、Agent 标识、状态、结论、适用前提、证据 ID 与待补事实。汇总必须引用原证据，不仅引用子 Agent 的自然语言回答。可解释的差异按条件展示，无法解释的冲突并列标明待复核。

## 五、法律信息与数据边界

### 5.1 产品边界

提供法律信息检索与辅助，不预测胜诉率、不承诺案件结果、不出具正式法律意见书。刑事辩护、紧急人身安全等超范围事项提供适当引导。免责声明不能代替质量、权限及责任分析。

不把所有出现“诈骗”“家暴”等词的问题一律拒答，应识别真实请求，必要时优先安全引导，并说明可处理的民事信息范围。

### 5.2 版本与适用

区分“查询时是否现行有效”与“对特定事实是否适用”。历史事实可能需要历史规定，不能将旧法机械替换成新法。缺少必要时间或其他事实时澄清或给出条件化说明。

每份法律资料记录官方来源、版本、生效与失效时间、核验人和时间。历史版本保留，未知状态明确标为待核验。基础阶段先用少量核验过的资料，大规模映射不是开工条件。

设计参考：[最高法关于适用民法典时间效力的若干规定](https://www.sdcourt.gov.cn/qdtlfy/368549/506706/6766513/index.html)。资料清单按选定场景复核相关新解释，包括[婚姻家庭编解释（二）](https://www.court.gov.cn/zixun/xiangqing/452771.html)、[劳动争议解释（二）](https://www.court.gov.cn/zixun/xiangqing/472691.html)。这些示例不是完整现行法规清单。

### 5.3 来源、更新与隐私

优先国家法律法规数据库、最高人民法院等官方来源。逐份记录链接、获取时间、内容哈希和使用条件；公开可访问不等于可以忽略使用条件与个人信息保护。不得伪造案号或来源。

指定维护人定期核验资料，演示前复核一次；发现修订时登记新版本、重新切块索引，并验证历史引用仍可追溯。

公共法律库与用户合同、会话分开存储，私人材料不进入公共检索。管理员维护知识库，用户仅访问授权资料和自己的会话。明确保留期限、删除入口、日志脱敏和云端模型传输范围；删除覆盖原文、向量、缓存及派生报告。演示优先使用虚构材料。上传内容作为资料，不能作为系统指令或工具授权。

## 六、验收与交付

### 6.1 基础验收

| 用例 | 动作 | 通过标准 | 对应要求 |
|---|---|---|---|
| BASE-01 | 五个 Agent 各问一个有依据的问题 | 各自业务配置生效，真实调用 RAG，回答符合职责 | REQ-01、04 |
| BASE-02 | 切换五个 Agent 菜单 | 页面、请求 Agent 标识、后端配置一致，会话不误串 | REQ-02、05 |
| BASE-03 | 上传此前未入库的测试文档 | 能预览、确认向量化并查询任务结果 | REQ-03 |
| BASE-04 | 检索新文档中的特定信息 | 返回真实片段，可展开原文定位 | REQ-03、05 |
| BASE-05 | 测空文件、无结果、模型超时 | 明确反馈及恢复入口，不展示虚假成功 | REQ-05 |
| BASE-06 | 删除测试文档后再检索 | 不再参与新回答，历史引用按保留策略处理 | REQ-03、05 |

### 6.2 附加题验收

| 用例 | 动作 | 通过标准 |
|---|---|---|
| COL-01 | 消费与诉讼程序综合问题 | 两个不同业务 Agent 真实执行 RAG，有分工及汇总 |
| COL-02 | 模拟一个子任务超时 | 明确部分完成及失败领域，不编造缺失结论 |
| COL-03 | 输入前提不同或冲突的子结果 | 展示条件差异或待复核冲突，不静默选边 |
| COL-04 | 请求未授权工具或递归协作 | 服务端阻止，数量与深度不突破限制 |
| COL-05 | 展开汇总引用 | 能追溯子任务、检索记录及原文，编号不混淆 |

### 6.3 质量与交付物

先维护 20 条开发用例，再建立至少 50 条独立验收用例，覆盖五域、无依据、事实不足、版本、权限及失败路径；协作用例另列。报告记录域内可回答率、错误拒答率、引用准确率、引用支持率、Recall@5 和延迟，注明分子分母、测试集版本、模型及语料快照。固定集全通过不代表开放场景零错误。

必做交付：源码、部署配置、示例环境变量、五个 Agent、三个 RAG 页面、核验过的演示资料和基础验收记录。

附加交付：协作 Agent 与菜单、任务分解及调用记录、统一引用、部分失败演示和 COL 验收记录。其他可选能力单列实际完成项。

需求文档回答“做什么与如何验收”；技术方案、接口、数据模型与实施顺序以配套规划书为准。
